# The new-issue form in a browser, 2026-11-20

A session drove Chrome on the operator's Mac, signed in to GitHub as the operator, on `sapientpants/sf-scratch`. Nothing was submitted successfully and no issue was created. A script in the page polled the value of each field every 20 to 25 ms and logged each change; times below are milliseconds on the page's clock. Keys were sent by the browser extension, not typed by a person.

## A field that a link prefilled goes back to the link's value

The page was opened from a link with `outcome=hello` and `acceptance-criteria=- AC-1 (review): a line.` in the query, and a `title`.

| Typed | Log of that field | Kept |
|---|---|---|
| ` abc` at the end of Outcome, four keys within 10 ms | 551 `hello abc`, 1076 `hello` | No: reset 525 ms later |
| `X` in Outcome | 141 `helloX`, 641 `hello` | No: 500 ms |
| `Y` in Outcome, 3 s later | 3161 `helloY`, 3661 `hello` | No: 500 ms |
| `1`, `2`, `3` in Outcome, 0.3 s apart | 32329 `hello1`, 32641 `hello12`, 32943 `hello123`, 33462 `hello` | No: all three kept until 519 ms after the last key |
| `A` at the end of Acceptance criteria | 30321 `...a line.A`, 30821 `...a line.` | No: 500 ms |
| `T` at the end of the title | 6633 `P-4 probe F: a word in OutcomeT` | Yes, for the 36 s the page stayed open |
| `S` in Spec refs, which the link left empty | 10182 `S` | Yes |
| `C` in Context, which the link left empty | 28281 `C` | Yes |
| `Q` in Outcome, after `history.replaceState` had taken the fields out of the address bar | 42961 `helloQ`, 43461 `hello` | No: 500 ms |

So a `textarea` that the link prefilled returns to the link's value about half a second after the last key. The title, which the link also prefilled, and the fields the link left empty keep what is typed. No focus change or other event on the field came with a reset. Taking the query out of the address bar afterwards changed nothing. Why the page does this was not looked into.
