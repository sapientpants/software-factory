# 08 - Fact-check of load-bearing research claims

Checked 2026-11-18 against primary sources (raw repo files, crates.io API, official docs fetched as markdown/HTML, the posts themselves). A claim is "confirmed" only where the evidence was opened and read in this pass.

Summary: 66 claims checked. 56 confirmed, 9 partly (8, 13, 19, 26, 34, 45, 50, 51, 60), 1 wrong (1), 0 unverifiable.

## Corrections the spec must absorb

1. **Symphony has a first-party GitHub Issues adapter (claim 1 is wrong).** The Elixir reference ships adapters for Linear, GitHub Issues, Jira Cloud, Asana and GitLab. The GitHub adapter (`tracker.kind: github`, added 2026-07-20) is minimal: states are only `open`/`closed`, `blocked_by` is always empty, PRs returned by the Issues API are not dispatchable, identifier is `GH-<number>`. It is prior art for the adapter boundary, not for a label- or status-driven workflow.
2. **SIGTERM to `claude -p` yields no result for the interrupted turn (claim 51).** The docs say Claude Code "records no result for it". The supervisor must not wait for a `result` line after SIGTERM; send SIGINT first (or close stdin as the Python SDK does) when a final result is needed.
3. **`GITHUB_TOKEN` events are not a blanket "no new runs" (claim 45).** `workflow_dispatch` and `repository_dispatch` always create runs, and `pull_request` opened/synchronize/reopened now create runs in an approval-required state. App installation tokens avoid the approval.
4. **Push rulesets need the GitHub Team plan (claims 26, 60).** "Restrict file paths" is a push rule; push rulesets are available only on GitHub Team (and Enterprise) for internal and private repositories. Rulesets on private repos need Pro/Team/Enterprise. Not usable on a Free personal-account private repo.
5. **Merge queue is not available on personal-account repositories (claims 22, 44, now verified on the fetched page).** Only organization-owned public repos, or private repos on Enterprise Cloud.
6. **Fabro has tagged non-prerelease releases (claim 13).** The latest non-prerelease is v0.254.0 (2026-06-04); everything since is nightly prerelease (v0.415.0-nightly.0 on 2026-11-12). Still 0.x.
7. **ACP Rust crate churn (claim 19).** 1.0.0 was published 2026-06-24 (announced 06-25); majors 2.0.0 (07-23), 3.0.0 (10-06), 5.0.0 (11-02) followed; 5.4.0 was published today. Pin exactly if used.
8. **OpenSpec is at 2.1.0, not 2.0 (claim 34).** 2.0.0 shipped 2026-11-11 and 2.1.0 on 2026-11-17; the 2.x line is one week old.
9. **`--bare` auth is not strictly `ANTHROPIC_API_KEY` (claim 50).** An `apiKeyHelper` in `--settings` also works, and Bedrock / Google Cloud / Foundry credentials are still read. OAuth and keychain are never read.
10. **Source attribution fixes.** The $200/6 h vs $9/20 min figures are in Anthropic's harness-design post, not the multi-agent-research post (claim 8). The 59-minute Copilot cap is on the about-cloud-agent page, not risks-and-mitigations (claim 5). The Cognition statement is in cognition.ai/blog/multi-agents-working, not the Cursor post (claim 11).

## Method notes

- GitHub docs were fetched as markdown via `docs.github.com/api/article/body?pathname=...`; "Who can use this feature" boxes are not in that output, so plan-availability statements were read from the rendered HTML pages.
- Claude Code docs were fetched as `.md` from code.claude.com.
- octocrab claims were checked by grepping the published 0.54.9 crate tarball, not the docs.rs summary.
- Crate versions come from `max_stable_version` in the crates.io API.
- Not re-verified: the OpenAI harness-engineering post (HTTP 403 from two fetchers).
